# Sauda Shastra — Indian markets, explained for traders and investors

**Sauda Shastra** (सौदा शास्त्र, “the science of the trade”) is a free, static, source-verified knowledge site: how Indian markets work for intraday and options traders, the technical analysis traders actually use, playbooks written to one fixed template, macro and events in IST, algo and systematic trading in India, risk, psychology and tax, long-term investing in India and the USA, and a ranked library of courses and books. Sources, not tips.

Live: https://sudish007.github.io/sauda-shastra/

## Stack

Node ≥ 24, plain ESM, one dependency (`marked`), `node:test`. No framework, bundler, server or database. Output is a static `dist/` deployed to GitHub Pages under `/sauda-shastra/` by `.github/workflows/pages.yml` (Pages source = GitHub Actions); every URL is relative and the 404 page pins `<base href>`.

```
npm install
npm run build     # content/ → dist/
npm run serve     # http://127.0.0.1:8790/sauda-shastra/
npm test          # content validation, markdown, built HTML, links, SEO, identity
```

## Verification

`npm test` covers the content validators, the renderers and the built HTML. The real-browser audits run on a Python venv with Playwright (the scripts launch Edge, `channel="msedge"`) against a served build (`npm run build`, then `npm run serve` or `PORT=8791 node scripts/serve.mjs`):

```
python scripts/shots.py [base_url] [out_dir] [--pages a/,b/] [--all-articles]   # screenshots + the numeric UI audit matrix, audit.json, exit 1 on any finding
python scripts/contrast.py                                                      # WCAG AA for the 21 token pairs × 2 themes, read from site/styles.css
python scripts/e2e.py [base_url]                                                # functional smoke test; prints "skipped (no data yet)" for data later steps add
python scripts/linkcheck.py [--resources] [--out file] [--no-browser]           # library link health → content/data/library/health.json; exit 1 when a link is dead
```

`linkcheck.py` reads `content/data/library/courses.json` and `books.json` (plus `content/data/resources.json` with `--resources`), fetches every unique URL with a browser User-Agent — HEAD first, GET when HEAD is not 2xx, redirects followed (≤ 10), 30 s timeout — and spaces requests to one host (≥ 15 s zerodha.com, ≥ 13 s wiley.com, ≥ 6 s amazon.in, ≥ 2 s elsewhere). Anything still failing is re-checked in headless Edge: a 2xx render, or an anti-bot interstitial (Amazon's "automated access" 503, Cloudflare's "Just a moment", Akamai's "Access Denied"), is classed **blocked** (the host refuses scripts but opens for visitors; kept and listed); everything else is **dead**. It writes `{ "checked", "urls", "ok", "blocked": [], "dead": [] }`, prints a table and exits 1 when `dead` is not empty. A full library run takes about ten minutes. The report is committed with the data it describes because the Pages build has no network step; the Learn page reads it for its hero card and "How we checked" footer, `npm test` asserts `dead` is empty, and the ship step re-runs the script before deploying.

`shots.py` audits the page list of the design (home, guides index, first guide, playbooks index, first playbook, tools index, first tool, learn, glossary, calendar, changelog, resources, facts, about, sources, 404 via an unknown nested path; articles that do not exist yet are skipped) at 320 (audit only), 390, 820, 1024 (audit only), 1440, 1920 and 2560 (device scale factor 0.75, so the shot is 1920 × 1080) in both themes; screenshots are viewport-only, named `<page>-<width>-<theme>.png`. `--pages guides/x/,tools/y/` adds pages to the audited and shot set (named by their path); `--all-articles` audits every guide, playbook and tool from `data/search.json` at 320 and 390 without screenshots.

## Where things live

- **Identity** — `src/build/config.js` is the one constant for the site name, slug, base path, localStorage prefix, owner, repo and live URL. Renaming the site is a change there plus `name` in `package.json` (a test keeps them equal).
- **UI strings** — `src/build/strings.js`; the client receives its strings through `<template id="ui-strings">`, so `site/app.js` has no literal UI text. No string may hold a fact value (figures reach strings through placeholders filled at build) and none names the project's internals; `tests/design.test.js` checks both.
- **Build** — `src/build/{content,markdown,templates,pages,site,dates,tools}.js`; `scripts/build.mjs` writes `dist/`. `tools.js` is the calculator registry (`{ id, title, summary, guide, factIds, fields, examples, schema }`); `tools/` and `tools/<id>/` render from it and `tools:` front matter is validated against its ids.
- **Client** — `site/app.js` (three-state theme Light → Dark → System, search dialog, mobile menu, TOC scrollspy, reading progress, calendar filters, library filters and ranking, facts-register filter), `site/tool-ui.js` (the calculator pages, loaded as an ES module there only), `site/styles.css` (the design system: tokens, fill grids, article layout), self-hosted fonts in `site/fonts/`. The current nav item is marked at build time from each page's `layout({ current })`; the client never infers it.

## Calculators

Eight client-side tools at `tools/<id>/`: `charges` (what a trade costs), `position-size`, `expectancy-kelly`, `expected-move`, `black-scholes-greeks` (with an implied-volatility solver), `fo-tax-estimator` (new regime, Income-tax Act 2025), `sip-compounding` (with inflation) and `us-vs-india-investing-cost`. No backend and no network call: nothing typed leaves the browser.

- **One implementation, three consumers.** `src/tools/calc.js` holds the maths (pure ESM, no DOM), `src/tools/rates.js` reads register value strings into numbers (`num("0.15%") → 0.0015`, `num("₹307 per crore") → 307`, `slab("₹4,00,001–₹8,00,000: 5%") → { lo, hi, rate }`), `src/tools/format.js` formats ₹ en-IN / $ en-US, and `src/tools/view.js` builds the result markup. The build renders Example 1 into each page with them, `node:test` runs pack L's worked examples through them, and the build copies the folder to `dist/tools/` so `site/tool-ui.js` runs the very same code in the browser.
- **Rates come from the register.** Every statutory figure a tool uses is a `facts.json` row listed in the tool's `factIds`; the page's "Rates used" block shows each with its source, `since` and `verified` dates, and the formula disclosure is generated from the register values and the current inputs (never typed). Broker figures (brokerage models, DP charge) are register rows labelled "(broker example)" and editable in the form. Fact-dependent copy in `strings.js` uses `{placeholders}` filled at build with plain `.fact` spans.
- **Rounding rule (pack L, binding).** Every money line is rounded half-up to the paise as it is computed; totals are sums of rounded lines; Greeks show four decimals, implied volatility two decimals in percent. `r2()` in `calc.js` is the one rounding function.
- **Live, with two worked examples.** No Calculate button: results recompute on every `input`; the only live region is a visually-hidden `role="status"` line updated 400 ms after the last keystroke. Two chips (`aria-pressed`) load the worked examples, a manual edit releases them, and one button reads "Reset to example n". Invalid input marks the field (`aria-invalid` + `.hint.error`) and the result shows "—", never NaN. The registry's `examples[].expect` maps hold pack L's exact figures: `tests/tools.test.js` checks them against `calc.js` key for key and `scripts/e2e.py` reads them from the page's `<template id="tool-examples">` and compares every `[data-result]` in the browser.
- **Validation.** `calc.js` throws a `RangeError` carrying `field`, `min` and `max` on out-of-range input (design §9 bounds); the client validates the visible fields first and maps a thrown error back to its field.

## Content model

- `content/guides/<slug>.md` — front matter: `title`, `section` (one of the ten sections in `content.js`), `summary`, `updated` (YYYY-MM-DD), `level` (beginner | intermediate | advanced), `reading_time` (minutes; computed if absent), `topics`, `related` (guide or playbook slugs that exist), `tools` (optional; calculator ids from `src/build/tools.js`, rendered as the rail's Tools card), `sources` as `Title | URL | accessed YYYY-MM-DD`. Body in Markdown with `:::note|tip|warning|rule|example|evidence` callouts. The `summary` may use `{{fact:id}}` tokens (rendered plain on cards and in the lede; reduced to the value for meta and search).
- `content/playbooks/<slug>.md` — same fields plus `instruments`, `window` (IST), `glance_stop`, `glance_target`, `glance_size` (≤ 90 characters each; they fill the at-a-glance grid with Instruments and Window) and `evidence` (EVIDENCE | MECHANISM | LORE). The body must contain these h2 headings in this order: Context & instruments → Time window (IST) → Pre-conditions → Entry → Stop → Target / exit → Position-size rule → When NOT to trade → Known failure modes → Evidence label → Schematic. The schematic is `<figure class="schematic">` holding an inline `<svg>` with **no `<text>`** (every word lives in the `<figcaption class="legend">`, which ends with “Schematic, not real data.”). Sources render from front matter after the body. The build fails on a wrong order, a missing glance field, words inside the SVG or a missing legend. Start from `content/_templates/playbook.md`; the loader reads `content/guides`, `content/playbooks` and `content/pages` only.
- `content/pages/<slug>.md` — stand-alone pages (today `about.md`): front matter `title`, `summary`, `updated`, optional `sources`; body Markdown. Exposed to the renderers as `c.pages.<slug>`.
- Inline tokens in any Markdown body: `{{fact:id}}` renders a register value — the first use on a page shows `✓ <verified date>` linking to the rail entry (its title is `source · since|from <date> · verified <date>`), every later use renders the value plain, and a value whose `since` is still in the future carries “(from <date>)”. `{{label:EVIDENCE|MECHANISM|LORE}}` renders the evidence chip (● Evidence · ◐ Mechanism · ○ Lore) so labels are consistent and countable.
- `content/data/facts.json` — the verified facts register (rendered at `facts/`): every rate, lot size, expiry day, threshold and statistic that changes. Array of `{ "id", "label", "value", "since", "source", "verified" }`: `id` lowercase-kebab with one of the nine group prefixes `mkt`/`fo` (sessions & derivatives), `chg`, `opt`, `sebi`, `tax`, `mac`, `algo`, `inv`, `glb`; `value` the bare figure with its unit (`"0.1%"`, `"₹307 per crore"`, `"65"`, `"15:40 IST"`) — ≤ 60 characters when any page tokens the id (fatal; a warning above 40), ≤ 120 for register-only rows — with qualifiers in the `label`; `since` the date the value took effect; `source` as `Title | URL`, where the title names the enacted instrument or circular (“Finance Act 2026, s. 159”, “NSE circular FA/73061”) — a Finance Bill clause or a Budget memorandum fails the build; `verified` the date it was last checked. Prose never types these numbers: `tests/design.test.js` scans every built page for a register value typed within six words of its label words, and `src/build/strings.js` for any fact value at all. The five home-hero facts (`sebi-loss-2026-share`, `-amount`, `-avg`, `sebi-costs-share`, `sebi-loss-2026-five-year-consistent`) must exist with one shared `verified` date whenever the register is non-empty.
- `content/data/glossary.json` — `[{ "term", "def", "see": [] }]`; `def` may use `{{fact:id}}`.
- `content/data/calendar.json` — `{ "note", "filters": [{ "id", "label" }], "events": [{ "date": "YYYY-MM-DD" | "rule", "what", "kind", "time_ist", "source" }] }`; every event's `kind` must be a filter id.
- `content/data/changelog.json` — `[{ "date", "what", "detail", "source", "affects": [slugs] }]` for the “What changed” page.
- `content/data/resources.json` — `[{ "category", "name", "url", "what" }]`; every named item is a link.
- `content/data/library/courses.json`, `books.json` — `[{ "id", "title", "by", "type" (course | book | paper | video series | newsletter), "cost" (free | paid), "price": { "amount" (as the provider shows it, e.g. "₹1,500 + taxes"), "currency", "seen" }, "links": [{ "label", "url" }] (official or publisher page first, one retailer search last, never affiliate links), "year", "level", "fits": [...], "hours" | "pages" (a number; rows with neither show their "effort" text), "effort", "why", "caveats", "rank": { "<fit>": n } (one rank per fit, per list; gaps allowed), "forthcoming": true (no rank; sorts last), "credential", "freeCopy" }]` (`why` and `caveats` are both required); `fits` ⊂ intraday | options | algo | India investing | US/global investing | risk & psychology | tax & rules. `library/path.json` — `{ "intro" (must start "Our editorial judgement, not advice"), "stages": [{ "title", "hoursPerWeek", "steps": [{ "entry": id, "note" }] }] }`; every `entry` must be a library id. `library/health.json` — written by `scripts/linkcheck.py` (`{ "checked", "urls", "ok", "blocked", "dead" }`); the Learn page shows "links checked: not yet" and the build warns when it is missing. The build emits `data/library.csv` (`id,kind,title,by,type,cost,price,currency,price_seen,links,year,level,fits,hours,pages,why,caveats`; links separated by spaces, fits by `; `).

Routes: `/`, `guides/`, `guides/<slug>/`, `playbooks/`, `playbooks/<slug>/`, `tools/` (index of the registry), `learn/` (the library: a two-column hero with the counts and link-health card, Cost chips All/Free/Paid, seven Fit chips that rank the rows by their `rank` for that fit, Level and Type selects, a text filter, “Download CSV”, the three-stage recommended path linking `#<id>` rows, then the Courses and Books-and-papers tables — eight columns from 1440 px, stacked cards below — and the “How we checked” footer), `glossary/`, `calendar/`, `changelog/`, `resources/`, `facts/` (the register: nine group chips, a text filter, “Download JSON” → `data/facts.json`, and a table of value · source · since/from · verified · used on), `about/`, `sources/`, `404.html`. Home-page counts (guides, playbooks, calculators, glossary terms, sources) are computed at build and also written to `dist/data/counts.json`; `data/search.json` indexes guides, sections, playbooks, tools, terms, courses and books (`learn/#<id>`), facts (`facts/#fact-<id>`) and pages.
